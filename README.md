# Grand Heist

Grand Heist — адаптивный прототип видеослота 5x5 на Svelte. В текущей версии реализованы локальный игровой клиент, последовательное воспроизведение результата раунда и GSAP-анимации вращения барабанов, выигрышных линий, счетчика выигрыша и экранов Big/Mega/Epic Win.

ссылка на игру: https://grand-heist-tau.vercel.app/
## Требования

- Node.js 20+
- pnpm 11.0.3 (`corepack enable` при необходимости)

## Запуск

Из корня репозитория:

```bash
pnpm install
pnpm --filter @grand-heist/app dev
```

Приложение будет доступно по адресу `http://127.0.0.1:5173`. Порт может измениться, если 5173 занят.

В текущем прототипе реальный backend не нужен: `installMockPlayApi()` перехватывает `POST /api/play` в браузере и по кругу возвращает подготовленные сценарии. Для отладки проигрывателя можно открыть приложение с `?dev=1`; тогда в `window.grandHeistRoundPlayer` доступны mock-раунды и метод `play(roundId)`.

## Проверка и сборка

```bash
pnpm check
pnpm build
```

- `pnpm check` запускает TypeScript/Svelte-проверки во всех пакетах через Turborepo.
- `pnpm build` сначала собирает общий контракт, затем production-версию приложения.
- Результат приложения находится в `apps/grand-heist/dist`.

На контрольном прогоне 14 октября 2026 года обе команды завершились успешно. `svelte-check` показал 0 ошибок и 30 предупреждений: это существующие a11y-предупреждения для интерактивных `main`/`section` и неиспользуемые CSS-селекторы.

## Деплой

Приложение собирается как статический сайт. В `vite.config.ts` задан `base: './'`, поэтому каталог `apps/grand-heist/dist` можно разместить как в корне домена, так и в подпапке.

Универсальный вариант:

```bash
pnpm install --frozen-lockfile
pnpm build
```

После сборки нужно опубликовать содержимое `apps/grand-heist/dist` через Nginx, S3/CloudFront, GitHub Pages, Netlify или Vercel. Для Netlify/Vercel параметры проекта такие:

| Параметр          | Значение                         |
| ----------------- | -------------------------------- |
| Root directory    | корень репозитория               |
| Install command   | `pnpm install --frozen-lockfile` |
| Build command     | `pnpm build`                     |
| Publish directory | `apps/grand-heist/dist`          |

Важно: production-версия сейчас также устанавливает browser mock для `/api/play`. Перед подключением backend нужно убрать `installMockPlayApi()` из `apps/grand-heist/src/main.ts`, настроить URL API и при необходимости proxy/CORS.

Анимации барабанов выполняются через `transform` и `filter`, а не через изменение layout-свойств. GSAP выбран вместо набора CSS-анимаций, потому что вращение зависит от асинхронного ответа API: таймлайн должен циклически проигрываться до ответа, выдерживать минимум 900 мс, затем бесшовно перейти к нужным символам и разрешать программный skip.

## Проигрыватель результата

Поток разделен на данные раунда, их последовательное воспроизведение и визуальные таймлайны.

1. `LocalGameClient` отправляет `POST /api/play` и преобразует массив событий в `RoundResult` с `events` и `finalState`.
2. Событие `reveal` содержит конечную сетку барабанов, `lineWin` описывает линию, ячейки и сумму, `totalWin` содержит общий выигрыш.
3. `RoundPlayer` — универсальный последовательный проигрыватель. Он перебирает известные события, ожидает завершения каждого обработчика и поддерживает отмену текущего события через `AbortController`. Неизвестные события безопасно пропускаются.
4. `AnimationController` отвечает только за визуальную сторону: хранит GSAP-таймлайны, запускает/останавливает барабаны, подсвечивает линии, считает выигрыш, показывает Big/Mega/Epic Win и очищает активные эффекты в `destroy()`.
5. `App.svelte` связывает клиент и анимации. При нажатии Spin сразу запускается `startSpin`, параллельно ожидается API, затем выполняются `stopSpin`, подсветка линий и счетчик. После завершения анимаций применяется `finalState` и обновляется баланс.

Основной сценарий:

```text
Spin
  -> startSpin + POST /api/play
  -> reveal / stopSpin
  -> lineWin + win counter (параллельно)
  -> finalState и баланс
  -> Big/Mega/Epic Win при результате >= 20x ставки
```

ЛКМ или пробел пропускают текущую допускающую skip анимацию. На экране большого выигрыша первый skip завершает счетчик, второй закрывает экран. Пороги: Big Win от 20x, Mega Win от 40x, Epic Win от 80x; длительность счетчика соответственно 3, 5 и 8 секунд.

## Изменения структуры проекта

По сравнению с исходным состоянием добавлено разделение ответственности:

```text
apps/grand-heist/src/
├── App.svelte                         # UI и интеграция игрового потока
├── main.ts                            # bootstrap приложения и mock API
└── lib/
    ├── animation-controller.ts        # GSAP-таймлайны и skip/cleanup
    ├── round-player.ts                # последовательный player событий
    ├── client/
    │   ├── local-game-client.ts       # клиент /api/play и сборка finalState
    │   └── mock-play-api.ts           # локальный fetch-mock
    └── fixtures/mock-states.ts        # сценарии loss/line/big/mega/epic

packages/grand-heist-contract/src/
└── index.ts                           # общий контракт сетки, событий и раунда

.agents/spec/
└── animations.md                     # спецификация и checklist анимаций
```

Ключевые изменения:

- игровая сетка разбита на пять независимых барабанов с верхним и нижним буферами;
- типы `RoundEvent`, `RoundResult`, `ReelGrid` и координат вынесены в общий workspace-пакет;
- API-слой отделен от UI и может быть заменен реальным transport без изменения формата раунда;
- логика таймлайнов вынесена из компонента в `AnimationController`;
- добавлен независимый `RoundPlayer` для последовательной обработки событий и отмены;
- добавлены mock-сценарии и dev-интерфейс для проверки разных исходов.

## Что выполнено

- Анимация старта слева направо с шагом 80 мс, откатом на 8 px и циклическим вращением.
- Минимальное время вращения 900 мс и остановка слева направо с шагом 160 мс.
- Подстановка символов из `reveal`, снятие blur и отскок на 10 px.
- Последовательная подсветка выигрышных линий и пульсация символов.
- Счетчик выигрыша за 600 мс и отложенное применение финального состояния.
- Экраны Big/Mega/Epic Win с переходом между уровнями и двухшаговым skip.
- Skip мышью и пробелом, блокировка повторного spin, cleanup таймлайнов при размонтировании.
- Локальный `/api/play`, типизированные mock-раунды и dev-хук проигрывателя.

## Что не успел

- Инструментально проверить FPS на согласованной матрице устройств. Сделал бы сценарный Playwright-прогон с CDP tracing, фиксированными viewport/device profiles и отчетом по frame time, dropped frames и long tasks.
- Добавить unit/integration-тесты для `RoundPlayer`, `AnimationController` и полного flow. Для таймлайнов использовал бы fake timers, для UI — Playwright со сценариями из `.agents/spec/animations.md`.
- Подключить реальный backend. Mock нужно включать только в dev-режиме, URL вынести в env, добавить валидацию ответа и обработку timeout/retry/error-state.
- Оптимизировать ассеты. Конвертация PNG в WebP/AVIF, responsive-варианты и lazy/preload-стратегия дадут наибольшее снижение текущих 23,54 MiB.
- Устранить 30 предупреждений `svelte-check`: заменить интерактивные `section` подходящими элементами/обертками и удалить либо актуализировать неиспользуемые CSS-селекторы.
- Реализовать частицы монет для Big/Mega/Epic Win: отдельный переиспользуемый particle-layer с object pool, ограничением количества частиц и отключением/упрощением при `prefers-reduced-motion` или слабом устройстве.
- Провести тест на отсутствие утечек listeners и таймлайнов после сотен spin.
